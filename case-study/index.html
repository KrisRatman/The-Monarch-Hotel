The Monarch Hotel

Кастомная WordPress-тема для отеля: адаптивный лендинг на Tailwind CSS снаружи и рабочая мини-CRM заявок на бронирование внутри админки — без конструкторов и универсальных плагинов, каждая часть написана под задачу.

02 Фронтенд + бэкенд

Заявка на бронирование

Форма отправляется без перезагрузки страницы через fetch в admin-ajax.php, а не почтовым плагином. Это даёт контроль над каждым шагом — от первой подсказки пользователю до письма ему на почту.

1

Клиентские подсказки. Дата заезда не может быть раньше сегодняшнего дня, дата выезда — раньше даты заезда; ошибка показывается сразу, без похода на сервер.

2

Honeypot вместо капчи. Скрытое поле website невидимо человеку, но его заполняют боты — такие заявки тихо «принимаются» и никуда не сохраняются.

3

Nonce на каждый запрос. AJAX-запрос подписан одноразовым токеном monarch_booking_nonce — сервер проверяет его через check_ajax_referer() до того, как прочитать хоть одно поле.

4

Серверная валидация — по-настоящему. Имя, телефон, тип номера из закрытого списка, корректные и непротиворечивые даты, формат email — всё перепроверяется на PHP, клиентским подсказкам сервер не доверяет.

5

Заявка попадает в WordPress. Успешная отправка создаёт запись типа booking_request сразу со статусом «На рассмотрении» — и письмо уходит и администратору, и гостю.

Гостей2

Реконструкция реального интерфейса по коду темы — не скриншот; имена гостей вымышлены.

▤

Скрытый CPT с открытым интерфейсом. booking_request зарегистрирован с public = false, но show_ui и show_in_menu включены — заявки нельзя открыть по прямой ссылке на сайте, но у них есть полноценный раздел в админке со своей иконкой.

▥

Свои колонки в списке. Стандартные «Автор/Дата» заменены на «Статус, Гость, Телефон, Номер, Даты, Email» через manage_{cpt}_posts_columns — весь смысл заявки виден без открытия карточки.

▾

Фильтр по статусу. Выпадающий список над таблицей добавлен через restrict_manage_posts и сужает выборку через pre_get_posts — менеджер видит только то, что «На рассмотрении», одним кликом.

✓

Смена статуса в один клик. Ссылки «Подтвердить / Отклонить / Вернуть в ожидание» — это подписанные nonce-ссылки на admin_action_monarch_booking_status, с проверкой current_user_can('edit_post') перед записью.

◆

Карточка заявки. Meta box «Детали заявки» собирает все поля гостя и повторяет те же кнопки статуса — принять решение можно и из списка, и открыв заявку целиком.

04 Под капотом

Как это защищено и собрано

Безопасность

  • Nonce на AJAX-приёме заявки и на каждой ссылке смены статуса
  • Проверка прав (current_user_can) перед любым изменением статуса
  • Honeypot-поле против ботов — без внешней капчи
  • Серверная валидация не доверяет клиентской
  • Отключён XML-RPC, убраны RSD/wlwmanifest/generator-теги из <head>

Сборка и эксплуатация

  • Tailwind CLI: npm run dev (watch) / build (minify)
  • Собранный CSS коммитится в тему — на проде Node.js не нужен
  • Гугл-шрифты Playfair Display + Manrope, без веб-конструктора
  • Двойное письмо: администратору — заявка, гостю — подтверждение
function monarch_booking_submit() {
    if ( ! check_ajax_referer( 'monarch_booking_nonce', 'nonce', false ) ) {
        wp_send_json_error( [ 'message' => 'Сессия устарела…' ] );
    }

    // honeypot: реальные гости это поле никогда не заполняют
    if ( ! empty( $_POST['website'] ) ) {
        wp_send_json_success( [ 'message' => 'Спасибо! Заявка отправлена…' ] );
    }
    // … дальше — серверная валидация полей и wp_insert_post()
}
add_action( 'wp_ajax_monarch_booking_submit', 'monarch_booking_submit' );
add_action( 'wp_ajax_nopriv_monarch_booking_submit', 'monarch_booking_submit' );

inc/booking.php — обработчик заявки: проверка сессии и honeypot идут раньше, чем сервер прочитает хоть одно поле формы.
